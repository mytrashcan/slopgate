# 강연 정리 — All Code Is Slop (Except Mine)

Lauren Tan (poteto), AI Engineer, 2026-11-14. 길이 17분.
원문 인용은 자동 자막 기준이라 문장이 매끄럽지 않다. 주장만 정확히 옮긴다.

## 숫자

- 개인 3,000 PR / 한 달, 팀 11,000 PR / 한 달
- revert 비율 약 0.5%로 안정 (속도가 올라도 나빠지지 않음)
- 기여자 227명 (한 달에 PR 1개 이상)
- 스스로 "여기까지 6개월 걸렸다"고 말함 — 단축 가능하다고 덧붙임
- 한 엔지니어의 토큰 대부분이 검증에 쓰임 ("70%는 검증"이라는 외부 사례를 인용하며 동의)
- 주석: 7월 말 65,824개 → 현재 1,227개 (해설 영상 기준)
- "교정을 린트·설계로 옮긴 횟수" 계단 그래프: 7 → 167 (해설 영상 기준)

## 한국어 해설 영상이 보태는 것 (AgentOS, 2026-11-15)

같은 발표를 한국어로 재해설하며 슬라이드 세부를 짚은 영상: <https://youtu.be/ueA116hO_ho>
발표 클립 + 해설 형식이라 원본에 없는 디테일이 있다.

- **피라미드 다섯 칸의 실제 명칭**: 코드베이스 · 정적 분석 · 검증 · 산문 · **사람 리뷰**. 위가 넓고 아래가 좁다.
  즉 사람 리뷰는 가장 좁은 맨 아래 칸이다 — 리뷰는 품질의 주 수단이 아니라 최후 수단이라는 뜻이고,
  내 `docs/01-model.md`도 이 순서로 고쳐야 했다(처음엔 산문을 맨 아래로 놓았다).
- **커서 타임아웃 3건의 날짜**(2026-09-09, 10-03, 10-17): 한 줄 땜질 → 그 땜질을 정당화하는 주석 → 전파. 3주 만에 관례가 된 과정.
- **런타임 검증 데모 3줄**: 설정 버튼 클릭 → 화면 상태 캡처 → 스크린샷을 증거 파일로 남기기. "사람은 코드가 아니라 증거를 본다"의 구체형.
- **릴리스 간격 중앙값**: 9월 25시간, 10월 28시간 (발표 중 말로는 "하루 한 번쯤"이라 했는데 슬라이드 수치와 다르다).
- **성능 각주**: Electron에는 천장이 있고 Rust 재작성을 검토 중이라고 화면에 적혀 있었다.
- **해설자의 단서**: 팀 수치는 로렌 탄이 직접 제시한 값이고 외부에서 확인할 자료가 없다고 밝힌다.
  → 우리 지표(`docs/05-metrics.md`)도 "누가 어떻게 측정했는가"를 함께 적는다.
- **같은 방향의 다른 발표**: Anthropic의 Lydia Hallie — "CLAUDE.md에 강조 문구를 쌓지 말라". 산문 층을 얇게 유지하라는 같은 결론.

해설자가 뽑은 "오늘 내 저장소에 넣을 수 있는 것" 3가지도 같은 결론이다.
① 같은 실수를 두 번 하면 규칙 파일에 한 줄 보태기 전에 린트/테스트로 만들 수 있는지 본다.
② 새로 생기는 것부터 막고, 이미 있는 것은 그다음에 치운다.
③ 에이전트가 자기 결과를 직접 실행해 확인할 통로(스크린샷·테스트 출력)를 하나 열어 준다.
주석 제거와 자동 병합은 "다른 이야기"라고 선을 긋는다 — 우리 범위 설정과 일치한다.

## 내 Hermes에 가져올 것

1. 교정 → 결정론 변환을 **규칙이 아니라 저장소 구조**로 만든다 (이 저장소의 `gates/`).
2. 산문(스킬·메모리·AGENTS.md)은 **줄이는 방향**으로만 늘린다. 늘릴 때는 "왜 검사로 못 만드는가"를 먼저 답한다.
3. 검증 산출물 중심 리뷰: PR 리뷰에서 "코드를 읽었다"가 아니라 "게이트 출력 + 실제 실행 결과"를 근거로 남긴다.
4. 무인 실행(크론)은 후보 게이트가 있을 때만 모델을 띄운다. 이미 한 번 크게 당했다(30분마다 무조건 실행 → 483회·8,670만 토큰).
5. 전용 CLI 우선: 반복 작업은 스킬 산문에 절차를 적는 대신 스크립트(`~/.hermes/scripts/*`)로 만들고 스킬은 그것을 부르게 한다.

## 가져오지 않을 것 (이유 포함)

| 항목 | 이유 |
|---|---|
| TLA+/Lean | 내 산출물은 대규모 동시성 클라이언트가 아니라 소규모 웹/백엔드와 운영 자동화다. 학습·유지 비용이 발견하는 버그 수보다 크다. 게이트·속성 테스트로 대체 |
| 주석 99% 금지 | 기존 레포(ASL, contest-mcp 등)는 리뷰 문화가 다르고 이미 주석 기반 문서화가 있다. 소급 적용은 소음만 만든다. 새 레포에서만 실험 |
| 자동 머지 | 내 PR 규칙은 "리뷰 없이 머지 금지"다. 강연의 자동 머지는 리뷰를 대체할 만큼 코드베이스가 좋아졌을 때의 이야기이고, 그 조건을 아직 측정하지 않았다 |
| 하루 3,000 PR식 볼륨 목표 | 볼륨은 결과지 목표가 아니다. 내 지표는 revert율과 재작업률이다 |
