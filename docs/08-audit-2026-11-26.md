## V1 — 첨부 스킬 본문이 검사 밖에 있었다 (수정 완료)

증상: 주간 크론의 실효 프롬프트가 **61,750자**였는데 `cron_lint`는 "오류 0"이라고 답했다.
원인: `CRN001`이 `jobs.json`의 `prompt` 필드만 셌다. 첨부 스킬은 **본문 전체가 프롬프트에 주입**되는데
그 비용을 아무도 세지 않았다. 같은 구조가 다른 잡에도 있었다.

| 잡 | 프롬프트 | 첨부 스킬 본문 | 실효 프롬프트 |
|---|---|---|---|
| Hermes-sweeper PR 자동 리뷰 봇 | 2,918 | 113,265 (4개) | **116,183** |
| GitHub PR/Issue Monitor | 999 | 102,827 (3개) | **103,826** |
| SI-Weekly-Memory-Cron-Check | 787 | 0 (제거 후) | 787 |

수정: `CRN011`(실효 프롬프트 > 40,000자 경고) + `CRN012`(첨부 스킬 본문을 못 찾음).
`CRN001`은 그대로 둔다 — 그건 "cronjob update 페이로드가 잘린다"는 **다른 한계**이고 두 수치를 합치면
원인이 뭉개진다. 검증: 테스트 4개 추가(합산 경고·소량 통과·없는 스킬·경고는 exit 0), 총 54/54 통과.

이 조치 자체가 원칙 1의 예시다. 교훈을 스킬 산문에 적어두는 것으로 끝내지 않고, 그 교훈을 위반하면
빨간불이 켜지는 검사로 바꿨다.

## V2 — 리뷰가 검증 산출물을 보지 않는다 (수정 완료, 같은 날)

**처리**: 게이트가 증거를 먼저 수집해 후보 목록에 붙인다. 리뷰어는 수집하지 않는다.

`hermes-sweeper-gate.py` → 각 PR 후보 뒤에 한 줄:

```
EVIDENCE|mytrashcan/Rust-DMA#52|head=9c758e3|ci=10/10|fail=0|files=25|+364/-63|review=NONE|merge=CLEAN
```

설계 제약 두 가지를 지켰다:
- **타임스탬프 금지** — monitor 게이트는 출력 바이트를 해시해 변화가 없으면 에이전트를 띄우지 않는다.
  증거 줄에 시각이 들어가면 매 틱이 "변화"로 보여 48회/일 모델이 돌아간다. 실제로 2회 실행 md5 동일 확인.
- **pending을 숨기지 않음** — `ci=8/10+2pending`처럼 적는다. CI가 끝나는 순간 줄이 바뀌고, 그게 다시 볼 시점이다.

 런북(`hermes-sweeper-runbook`)에 "리뷰 첫 줄에 증거를 인용하되, `ci=none`이면 실제로 읽거나 실행한 것을
 적어라(검사가 통과했다고 암시하지 말 것)"를 추가했다. 프롬프트에도 후보 형식 설명 1줄을 넣었다.

검증: `--selftest`에 CI 집계·pending·ci=none·review 없음·PR 아닌 줄 스킵 케이스 추가(전부 통과),
실제 PR(Rust-DMA#52)에서 2회 실행 결과 동일.

이전 기록(판정 근거)은 아래에 남긴다.

### 수정 전 상태

`hermes-sweeper-runbook`(리뷰 크론의 정본)에는 "무엇을 근거로 판정하는가"가 코드 단위로 적혀 있고,
게이트 출력·CI 상태·실행 증거를 인용하라는 요구가 없다. 즉 리뷰가 코드를 다시 읽는 구조다.

측정 한계: 최근 sweeper 출력 12건이 전부 `no_change (agent run suppressed)`라 **실제 리뷰 본문 표본이 0건**이다.
"리뷰가 증거를 인용하지 않는다"는 것은 절차 문서 기준 판정이고, 실제 리뷰 품질은 표본이 생긴 뒤에 재야 한다.

다음 단계 후보(택일):
- (a) 런북에 "리뷰 첫 줄에 게이트·CI 출력 인용" 규칙 1줄 추가 — 산문 증가, 원칙 2에 역행
- (b) 리뷰 크론의 `monitor_script`가 PR의 CI 상태·게이트 결과를 수집해 주입하고 런북은 그것만 읽게 한다 — 원칙 5 방향

## V3 — 도구가 꺼진 채 그 도구를 지시하고 있었다 (수정 완료)

`CRN011`(실효 프롬프트)을 보고 첨부 스킬을 줄이려다 더 나쁜 것을 찾았다.

리뷰 크론의 `enabled_toolsets`는 `["terminal","file"]`이었다. 그런데 런북은 `skill_view`를 지시하고
있었다(hermaguard 사다리). `skill_view`는 toolset `skills`에 산다. 실측으로 확인:

```
enabled_toolsets=['terminal','file']            -> 8 tools, skill_view? False
enabled_toolsets=['terminal','file','skills']   -> 12 tools, skill_view? True
```

도구가 없으면 모델이 호출을 시도해도 실행되지 않고, 모델은 **"스킬을 읽었다"고 착각한 채** 리뷰를 쓴다.
설정 파일 어디에도 오류가 없고 게이트도 초록이었다. `delegate_task`도 같은 상태였다 —
`code-review` 스킬이 세 갈래 병렬 리뷰를 지시하는데 그 도구가 꺼져 있었다.

수정:
- 크론 `enabled_toolsets`에 `skills`·`delegation` 추가 (실측으로 12개 도구 확인).
- 첨부 스킬 4개 → **1개**(런북). 나머지 3개는 런북이 `skill_view`로 시점에 맞게 부른다.
  실효 프롬프트 **116,183 → 17,045자**(런북 13.7k + 프롬프트 3.4k). 런북이 커진 이유는 아래 두 절을 넣었기 때문이다.
- `CRN013`: 프롬프트·첨부 스킬 본문에서 `도구(` 패턴을 찾아 그 toolset이 `enabled_toolsets`에 있는지 검사.
  `no_agent` 크론과 `enabled_toolsets` 미지정(None)은 제외. 테스트 6개 추가(총 60/60).

## V4 — "확인 못 함"이 "할 일 없음"으로 위장됐다 (수정 완료)

리뷰 게이트 로그 4,736줄을 집계한 결과, **61틱이 소스 조회 실패 상태로 `idle`을 출력**했다.
5개 소스가 전부 `error connecting to api.github.com`으로 실패한 틱도 있었다.

이때 게이트는 아무것도 출력하지 않는다 → monitor 해시가 그대로 → 에이전트 억제.
즉 **네트워크 장애가 "리뷰할 PR 없음"과 완전히 같은 신호**였다. 침묵이 "확인했고 할 일 없다"를
의미해야 하는데, "확인조차 못 했다"도 침묵이었다.

수정:
- 게이트가 전 소스 실패를 세어 `fetch_fail_streak`로 저장하고, 3틱째·이후 12틱마다
  `GATE_ERROR|all 5/5 sources failed`를 출력한다(마일스톤만 → 비용 유한). 부분 실패(5개 중 1개)는
  장애로 치지 않는다.
- `RT006`: 상태 파일의 streak ≥ 3이면 오류. 테스트 3개 추가.
- `--selftest`가 프로덕션 상태 파일을 덮어쓰던 버그도 고쳤다(tempfile로 격리, 실행 전후 diff 확인).

## V5 — 문서가 스스로 낡는 구조였다 (수정 완료)

원칙 1("교정은 규칙이 아니라 검사로")을 이 저장소에 적용해보니, 가장 자주 반복한 교정은
**"문서에 숫자를 박지 마라"**였는데 그게 규칙으로만 있었다. 실측: 같은 테스트 개수를 다섯 번
(42 → 50 → 54 → 60 → 63), 스킬 개수를 세 번(968 → 969 → 970) 고쳤다. 고칠 때마다 문서가 낡았고,
낡은 숫자는 다음 세션이 그대로 인용했다.

수정: `gates/docs_lint.py`(DOC001). 문서에서 **상승하는 카운터**를 찾는다 — 테스트 체크 수,
`통과 N/N`, `테스트 N개`, `스킬 N개`, 게이트 집계(`오류 N · 경고 N`).

면제 규칙도 검사로 만들었다:
- 같은 줄에 날짜가 있으면 "그 시점 실측"이라 허용.
- 날짜가 붙은 절(`## 현재 기준선 (2026-11-26)`) 아래도 허용.
- 파일명에 날짜가 있는 스냅샷 문서(이 감사 문서 등)는 전체 면제 — 숫자를 지우면 증거가 사라진다.
- 우리 환경에서 변하지 않는 외부 사실은 그 줄에 `docs-lint: fixed`를 붙여 면제(pstack의 스킬 62개).

첫 실행에서 **15건**이 잡혔고 전부 고쳤다. 지금 0건.

검사 자체의 오탐도 테스트로 잡았다. 처음엔 "첫 5줄에 날짜가 있으면 스냅샷" 규칙을 썼는데,
`## 현재 기준선 (날짜)` 제목 하나로 문서 전체가 면제되는 구멍이 있었다 — 테스트가 실패해서 발견했고,
명시 마커(`docs-lint: snapshot`)로 바꿨다.
