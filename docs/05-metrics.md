# 지표

강연의 결론은 "토큰을 검증에 써라"였다. 그러려면 **지금 얼마나 쓰고 있는지**를 알아야 한다.
여기서는 측정 가능한 것만 정의한다. 측정 못 하는 지표는 목표로 삼지 않는다.

## 1. 검증 토큰 비율 (핵심)

**정의**: 전체 모델 토큰 중 검증·리뷰 역할이 쓴 비중.
**측정**: `~/.hermes/state.db`의 `session_model_usage` (`task` 컬럼이 역할. `''`는 메인 턴).

```sql
-- 최근 7일, 역할별 토큰
SELECT CASE WHEN task='' OR task IS NULL THEN 'main' ELSE task END AS role,
       SUM(input_tokens+output_tokens+cache_read_tokens+cache_write_tokens) AS tok
FROM session_model_usage
WHERE last_seen >= strftime('%s','now','-7 day')
GROUP BY role ORDER BY tok DESC;
```

**측정값 (2026-11-27 실행, 최근 7일)** — 재현: `python3 scripts/token_report.py --days 7`

| 역할 | 입력 토큰 | 비중 |
|---|---|---|
| main (메인 턴) | 20,203,751 | 86% |
| background_review | 3,059,469 | 13% |
| compression / title / approval | 141,715 | 1% |
| **합계** | **23,404,935** | 100% |

주의 1: `cache_read_tokens`(8억)는 캐시 재사용이라 실제 비용 기여가 작다. **입력 토큰 기준 비율**을 본다.
주의 2: `session_model_usage.last_seen`은 ISO 문자열이 아니라 **epoch 초(float)**다. ISO로 비교하면
조용히 0건이 나온다(이 스크립트를 처음 만들 때 실제로 그랬다).

해석: 검증 역할(`background_review`)은 13%다. 11-25 기준선에서는 3%였는데, 그사이 리뷰 크론이
증거 수집(`EVIDENCE`)과 스킬 로딩을 갖추면서 리뷰 1건당 실제로 읽는 양이 늘었다. 강연 사례(70%)와는
여전히 거리가 있지만 방향은 맞다.

목표: 검증 역할 비중을 측정 가능한 형태로 15% 이상으로 올린다. 올리는 방법은 "리뷰를 더 시킨다"가 아니라
**게이트·속성 테스트·실행 검증을 자동화해서 검증 자체를 싸게 만드는 것**이다.

## 2. 게이트 적발 수

**정의**: 주 1회 게이트 실행에서 잡힌 항목 수와, 그중 실제로 고친 수.
**측정**: 실행 로그를 `~/.hermes/state/slopgate/last.json`에 남기고 비교 (2단계에서 스크립트화).

목표: 적발 → 수정 비율 80% 이상. 적발 수가 계속 0이면 게이트가 죽었는지 의심한다.

## 3. 재작업률

**정의**: 머지된 PR 중 revert되거나, 같은 파일을 2주 안에 다시 고친 비율.
**측정**:

```bash
# revert 커밋 (레포별)
git log --since='60 days ago' --grep='^Revert' --oneline | wc -l
```

목표: 강연 팀의 0.5%를 기준선으로 삼되, 내 규모(월 수십 PR)에서는 1건이 곧 2~5%다. 비율보다 **추세**를 본다.

## 4. 리뷰가 잡은 결함 vs 게이트가 잡은 결함

**정의**: 같은 기간에 리뷰 코멘트로 지적된 실제 결함 수와, 게이트/CI가 막은 수.
**측정**: 리뷰 코멘트는 `gh`로, 게이트는 실행 로그로. 분류는 수동 1회/주.

목표: 게이트가 잡는 비중이 올라가면 리뷰는 설계·의도 검토로 옮겨간다. 이게 "리뷰가 얇아져도 되는" 증거다.

## 5. 스킬 인덱스 비용

**정의**: 세션 시작 시 주입되는 스킬 인덱스 문자수.
**측정**: `python3 gates/skill_lint.py --json`의 `summary.index_chars`.

**현재: 25,505자 (게이트 근사) / 24,841자 (실제 `clip_skill_description`)** — 예산 60,000 이내.
초기 118,731자 → 60자 클립 99,617자 → Q8 실행 후 24,659자 → SKL004 복구 10건 반영 25,505자.
활성 스킬 970 → 277개.

## 6. 오탐률

**정의**: 게이트가 낸 경고 중 "고칠 필요 없음"으로 판정된 비율.
**측정**: 경고 처리 로그에서 `fixed` / `allowlisted` / `false-positive` 태그 집계.

목표: 오탐 10% 이하. 넘으면 게이트 기준을 고치거나 게이트를 내린다. 오탐이 많은 게이트는 반드시 무시된다.
