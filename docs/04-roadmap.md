# 로드맵 — 방학 4단계

원칙: **측정 → 결정화 → 강제 → 자동화** 순서. 자동화는 검증 스토리가 선 뒤에만.
각 단계는 "끝났다고 말할 수 있는 조건"을 가진다. 조건을 못 채우면 다음 단계로 넘어가지 않는다.

- [x] 게이트 5종(정적 4 + 런타임 1) + 실행 스크립트

  Q2는 선택지 (b)의 전제였던 "30% 축소 필요"가 Q8 실행으로 사라져 (a) 60,000자 유지로 닫았고,
  Q5·Q6은 "내 의견"이 곧 결정이라 조건부/범위를 명시해 확정했다. 남은 Q3(`.archive/` 822건)은

목표: 게이트와 검증을 "가끔 하는 일"에서 "정해진 시점에 반드시 하는 일"로 바꾼다.

- [x] 판단 대신 증거: PR 리뷰가 증거 줄을 인용하도록 **게이트가 증거를 수집해 주입**한다 (2026-11-26)

## 4단계 — 자동화 (방학 이후, 조건 충족 시)

여기서부터는 강연의 "소프트웨어 팩토리"에 해당한다. **자동 머지는 하지 않는다.**

- [ ] 야간 팩토리: 이슈 목록 → 초안 PR 생성 → 게이트 통과 시에만 사람에게 올림
- [ ] 릴리스 후 fuzz/탐색 에이전트 (웹 앱 대상, 예: dcselfie·semo.dcselfie.win)
- [ ] 자동 머지 여부 재검토 — 조건: revert율 측정값이 일정 기간 낮게 유지되고, 리뷰가 잡는 결함이 게이트가 잡는 결함보다 적다는 증거가 있을 때

완료 조건: 사람이 개입한 비율과 자동 처리 비율이 수치로 보고된다.

## 하지 않을 것

- 게이트 없는 자동 수정 PR
- 리뷰 생략
- 볼륨(PR 개수) 목표 설정
