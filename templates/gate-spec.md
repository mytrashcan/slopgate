# 양식 — 게이트 명세

`docs/03-gates.md` 표에 한 줄 추가하기 전에 이 양식으로 먼저 쓴다.

```markdown
## <ID> <이름>

- **분류**: 구조 / 린트 / 런타임 / 예산
- **검사 대상**: (파일·디렉터리·DB·출력)
- **판정 규칙**: (한 문장. 구현과 1:1로 대응해야 한다)
- **등급**: 통과 / 경고 / 차단 — 차단은 "사람이 무시하면 안 되는 것"만
- **근거**: (실제로 겪은 실패. 날짜·수치 포함. 추측이면 "추측"이라고 쓴다)
- **오탐 위험과 구분 방법**:
- **실패 메시지**: (고치는 방법이 들어가야 한다)
- **실행**: 수동 / 크론 / PR 전 / 세션 시작
- **테스트**: 일부러 깨뜨려 잡히는 것을 확인한 방법
- **승격·강등 조건**:
```

## 좋은 게이트의 조건

1. **결정론적**이다. 같은 입력이면 같은 출력. 모델 호출이 들어가면 게이트가 아니라 판단이다.
2. **고치는 방법을 알려준다.** "SKL003 실패"만으로는 부족하고 "references/x.md가 없다. 만들거나 문장을 고쳐라"가 필요하다.
3. **오탐이 드물다.** 오탐 10%가 넘으면 사람은 게이트를 통째로 무시한다.
4. **빠르다.** 3초 안에 끝나야 습관이 된다. 오래 걸리는 검사는 크론으로 분리한다.
5. **게이트 자체가 리뷰 대상**이다. 검사 로직이 틀리면 잘못된 방향으로 전체를 조인다.
