# 양식 — 교정을 게이트로 바꾸기

같은 실수를 두 번째 겪었을 때 이 양식을 채운다. 첫 번째는 그냥 고쳐도 된다.
**채우는 데 5분이 안 걸리면 게이트로 만들 가치가 있고, 30분 넘게 걸리면 산문으로 남기고 그 이유를 적는다.**

```markdown
## 실수: <한 줄>

- 언제: YYYY-MM-DD
- 몇 번째: (1/2/3...)
- 증상: (에이전트가 실제로 한 일)
- 피해: (토큰·시간·오답·잘못된 머지 등 관찰 가능한 것)

## 왜 산문으로는 안 되는가

- 이 규칙을 이미 적어둔 곳: (스킬 경로 / 메모리 / AGENTS.md) — 있으면 "적혀 있는데도 반복됐다"가 핵심 근거다
- 산문이 실패한 이유: (읽지 않음 / 읽고도 판단이 갈림 / 상황이 예외로 보임)

## 어떤 검사로 바꿀 수 있나

- 검사 대상: (파일 / 출력 / 상태)
- 판정: (존재 / 길이 / 패턴 / 스키마 / 실행 결과)
- 실행 시점: (수동 / 크론 / PR 전 / 세션 시작)
- 실패 메시지 초안: "X를 Y로 고쳐라. 이유: Z" (고치는 방법이 메시지에 있어야 한다)

## 오탐 위험

- 정상인데 걸릴 수 있는 경우:
- 그 경우를 어떻게 구분하나: (경로 조건 / allowlist / 별도 플래그)

## 승격 조건

- 지금: 경고
- 다음으로 올릴 조건: (2주간 오탐 0건 등)
```

## 예시 (실제 사례)

- **실수**: 크론 프롬프트를 9,531자로 만들어 `cronjob_manage(update)`가 페이로드 잘림으로 실패.
- **왜 산문으로는 안 되는가**: 메모리에 "9.5k 넘으면 update 실패"라고 적혀 있었지만, 프롬프트를 쓸 때 길이를 세지 않았다. 규칙이 **쓰는 시점에 측정**되지 않았기 때문.
- **검사**: `jobs.json`의 `prompt` 길이 > 9,000자 → 오류.
- **오탐**: 없음(길이는 사실).
- **승격**: 이미 오류 등급.
